# Database Migration Structure

This directory contains Flyway migration scripts for the Jewelry Shop application.

## Migration Files

### V1__complete_schema.sql
- **Purpose**: Clean database schema recreation
- **Contains**: Drops existing tables and recreates with correct structure
- **Safe for**: All environments (development, staging, production)
- **Git Status**: ✅ Committed to repository
- **Note**: No ALTER statements - clean recreation approach

### V2__sensitive_data.sql
- **Purpose**: Sensitive data and admin setup
- **Contains**: Admin user credentials, real email addresses, production secrets
- **Safe for**: Development only
- **Git Status**: ❌ Gitignored (not committed)

### V3__test_data.sql
- **Purpose**: Test data for development
- **Contains**: Sample products, categories, test analytics events
- **Safe for**: Development only
- **Git Status**: ❌ Gitignored (not committed)

### V2__production_ready.sql
- **Purpose**: Production-safe data
- **Contains**: Roles, system configuration (no sensitive data)
- **Safe for**: All environments
- **Git Status**: ✅ Committed to repository

## UUID Strategy

**Consistent UUID Usage**: All primary keys use UUIDs for maximum security and consistency
- **Users**: UUID (auto-generated by PostgreSQL `uuid_generate_v4()`)
- **Roles**: UUID (auto-generated by PostgreSQL `uuid_generate_v4()`)
- **Products**: UUID (auto-generated by PostgreSQL `uuid_generate_v4()`)
- **Categories**: UUID (auto-generated by PostgreSQL `uuid_generate_v4()`)
- **Tags**: UUID (auto-generated by PostgreSQL `uuid_generate_v4()`)
- **SystemConfig**: UUID (auto-generated by PostgreSQL `uuid_generate_v4()`)

**Security Benefits**:
- ✅ **Unpredictable IDs** - Cannot be guessed or enumerated
- ✅ **No Sequential Leakage** - No information about record count or creation order
- ✅ **Distributed Safe** - Can be generated across multiple systems without conflicts
- ✅ **Future-Proof** - Works well with microservices and distributed systems

**Collision Handling**: 
- `ON CONFLICT (name) DO NOTHING` for roles and categories
- `ON CONFLICT (email) DO UPDATE` for users (updates existing)
- `ON CONFLICT (sku) DO NOTHING` for products
- `ON CONFLICT (user_id, role_id) DO NOTHING` for user roles

**Benefits**:
- ✅ Zero collision risk (PostgreSQL generates unique UUIDs)
- ✅ Graceful handling of duplicate data
- ✅ Idempotent migrations (can run multiple times safely)
- ✅ Maximum security with unpredictable identifiers

## Environment Setup

### Development
1. Run V1 (schema)
2. Run V2__sensitive_data.sql (admin setup)
3. Run V3__test_data.sql (test data)

### Production
1. Run V1 (schema)
2. Run V2__production_ready.sql (roles only)
3. Manually create admin user through secure process

## Security Notes

- Never commit sensitive data files to version control
- Use environment-specific configuration for admin credentials
- Rotate admin passwords regularly
- Monitor database access logs
